## 2. Segreti LEADS_* e vault su prod

### 2a. Segreti delle funzioni (env)

Controllo di cosa c'è già:

```bash
supabase secrets list --project-ref qomnpzerhbtstbnwxnqc | grep -E 'LEADS_|RESEND_API_KEY'
```

Impostare quelli mancanti:

```bash
supabase secrets set --project-ref qomnpzerhbtstbnwxnqc \
  LEADS_IP_SALT='<VALORE>' \
  LEADS_NOTIFY_EMAIL='<VALORE>' \
  LEADS_RETENTION_SECRET='<VALORE>'
```

| Segreto | Usato da | Se manca |
|---|---|---|
| `LEADS_IP_SALT` | `submit-lead` (hash dell'IP per il rate limit) | il lead si salva senza `ip_hash`: niente rate limit |
| `LEADS_NOTIFY_EMAIL` | `submit-lead` (destinatario della mail interna) | lead salvato, nessuna mail |
| `LEADS_RETENTION_SECRET` | `purge-leads` (header `X-Job-Secret`) | ogni chiamata → 401 |

`RESEND_API_KEY` esiste già su prod (usata da altre funzioni); la lista serve solo a confermarlo.

### 2b. Vault (cron `purge-leads`)

Studio → **prod** → SQL Editor. Prima il controllo:

```sql
select name, created_at, updated_at
  from vault.secrets
 where name in ('purge_leads_url', 'leads_retention_secret');
```

Se mancano, crearli (`leads_retention_secret` = **la stessa stringa** di `LEADS_RETENTION_SECRET` del passo 2a):

```sql
select vault.create_secret(
  'https://qomnpzerhbtstbnwxnqc.supabase.co/functions/v1/purge-leads',
  'purge_leads_url'
);
select vault.create_secret('<VALORE = LEADS_RETENTION_SECRET>', 'leads_retention_secret');
```

Se esistono già con un valore diverso, aggiornarli invece di crearli (`create_secret` su un nome esistente dà errore di unicità):

```sql
select vault.update_secret(
  (select id from vault.secrets where name = 'leads_retention_secret'),
  '<VALORE = LEADS_RETENTION_SECRET>'
);
```
